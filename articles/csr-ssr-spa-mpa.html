CSR vs SSR vs SPA vs MPA — The Confusion I Had

I initially thought these four terms were different names for the same architectural idea. The distinction became much clearer once I separated rendering from navigation.

What I Thought Initially

When I first heard these terms:

  • CSR — Client-Side Rendering
  • SSR — Server-Side Rendering
  • SPA — Single Page Application
  • MPA — Multi Page Application

I thought they were basically different names for the same architectural idea.

My initial mental model was something like:

React → CSR → SPA Traditional website → SSR → MPA

It looked simple.

It was also wrong.

The problem was that I was mixing two completely different questions together.

The First Question: Where Is the HTML Generated?

This is what CSR vs SSR is about.

SSR — Server-Side Rendering

With SSR, the server generates the HTML.

Browser │ │ request ↓ Server │ │ generates HTML ↓ Browser │ ↓ Displays HTML

For example, the server might send: 

<h1>Hello Sanjana</h1>

The browser didn't create that <h1>.

The server did.

That's Server-Side Rendering.

CSR — Client-Side Rendering

With CSR, the client/browser generates the UI using JavaScript.

The server might initially send: 

<div id="root"></div>

along with JavaScript.

Then the browser runs: 

const root = document.querySelector("#root");

root.innerHTML = "<h1>Hello Sanjana</h1>";

Now the browser created the <h1>.

That's Client-Side Rendering.

Where is the HTML/UI generated?

Server → SSR
Browser → CSR

Then I Thought SSR Was Only About the Landing Page

This was another misunderstanding.

I initially thought:

"When we're talking about CSR vs SSR, are we mainly talking about the landing page?"

No.

CSR vs SSR can apply to each page or view being rendered.

For example, an MPA could have:

/home ↓ Server generates HTML ↓ SSR /about ↓ Server generates HTML ↓ SSR /products ↓ Server generates HTML ↓ SSR

So SSR isn't synonymous with "the first page."

It simply means:

The server generated the HTML being rendered.

Then Came SPA vs MPA

This was where I realized I had actually been asking a different question.

CSR vs SSR asks:

Where is the HTML/UI generated?

SPA vs MPA asks:

How does navigation happen?

MPA — Multi Page Application

Suppose I'm on: 

/home

and click: 

About

The browser requests: 

/about

and receives a new HTML document.

/home ↓ click About ↓ request /about ↓ new HTML document ↓ /about

That's an MPA — Multi Page Application.

And that new page could itself be SSR.

MPA + SSR /home → Server → HTML /about → Server → HTML /products → Server → HTML

SPA — Single Page Application

Now imagine: 

/home

is already loaded.

I click: 

About

Instead of requesting an entirely new HTML document, JavaScript handles the navigation and updates the application.

/home ↓ click About ↓ JavaScript ↓ updates view ↓ /about

That's a SPA — Single Page Application.

The important idea is that the same application remains loaded while the displayed view changes.

The Part That Confused Me the Most

I initially thought:

SPA = CSR MPA = SSR

But that's not necessarily true.

These are two different dimensions.

CSR vs SSR

WHERE is the HTML/UI generated? Server ↓ SSR Browser ↓ CSR

SPA vs MPA

HOW does navigation work? New HTML document ↓ MPA Same application handles navigation ↓ SPA

They aren't synonyms.

So Can You Have SPA + SSR?

Yes.

This was another thing that initially seemed contradictory to me.

"If it's SSR, the server creates the HTML. If it's SPA, the browser handles the page. How can both happen?"

The answer is that they describe different parts of the experience.

A simplified SPA + SSR flow can look like this:

FIRST VISIT Browser ↓ request /home ↓ Server ↓ generates HTML ↓ Browser ↓ displays page ↓ JavaScript loads ↓ application becomes interactive

The initial page was server-rendered.

Then:

LATER click About ↓ JavaScript handles navigation ↓ About view

The application can now handle navigation without requesting an entirely new HTML document.

So in this simplified example:

The initial page is server-rendered, while subsequent navigation is handled on the client.

That's how SSR and SPA behavior can coexist.

But SPA Doesn't Always Mean "First SSR, Then CSR"

This is another important distinction.

A SPA can also be completely client-rendered:

/home ↓ Browser JavaScript ↓ CSR /about ↓ Browser JavaScript ↓ CSR /products ↓ Browser JavaScript ↓ CSR

So we shouldn't memorize:

SPA → first page SSR

That's not a rule.

Similarly, we shouldn't memorize:

React → CSR

React can be used with different rendering strategies.

The Mental Model That Finally Made Everything Click

Instead of trying to remember:

React = CSR SPA = CSR Traditional website = SSR MPA = SSR

I now think about two separate questions.

Question 1

Where is the HTML/UI generated?

Server → SSR Client → CSR

Question 2

What happens when I navigate?

New HTML document ↓ MPA Same application handles navigation ↓ SPA

And these can be combined.

Rendering ┌──────┴──────┐ SSR CSR │ │ └──────┬──────┘ │ independent │ Architecture ┌──────┴──────┐ MPA SPA

What I Was Actually Confusing

Looking back, most of my confusion came from treating these as one classification system.

I was really mixing up:

Rendering ↓ CSR / SSR

with:

Application/navigation architecture ↓ SPA / MPA

Once I separated those two questions, the concepts became much easier.

The Four Terms in One Table

Concept Question it answers
CSR Where is the UI/HTML generated? → Client
SSR Where is the UI/HTML generated? → Server
SPA Does the same application handle navigation without loading a new document?
MPA Does navigation load separate HTML documents?

CSR/SSR and SPA/MPA are not competing alternatives. They describe different aspects of a web application.

One Last Example

If I have:

/home ↓ server generates HTML /about ↓ server generates HTML /products ↓ server generates HTML

That's:

MPA + SSR

If I have:

/home ↓ server generates initial HTML JavaScript loads /about ↓ JavaScript handles navigation /products ↓ JavaScript handles navigation

That's a simplified example of:

SPA + SSR

And if the initial UI and subsequent views are rendered on the client:

/home → CSR /about → CSR /products → CSR

that can be:

SPA + CSR

What I Want to Remember

I don't need to memorize which framework belongs to which category.

I just need to ask:

Where was the HTML/UI generated?

And:

Did navigation load a new document or stay within the same application?

Those two questions tell me what I'm actually looking at.
