Modern JavaScript Concepts

What is JavaScript actually doing when we use these features?

When I first came across features like destructuring, spread, and rest, the syntax looked simple enough.

But there was one thing I wanted to understand:

What is JavaScript actually doing when we write these three dots, brackets, and question marks?

These features are often taught as syntax shortcuts. And technically, they are useful shortcuts.

But understanding the idea behind them makes the syntax much easier to remember.

So instead of memorizing six separate features, let's build the mental model behind each one.

Destructuring

Consider an object: 

const user = {
  name: "Sai",
  age: 24,
  city: "Dallas"
};

If we want the name and age, we could write: 

const name = user.name;
const age = user.age;

There is nothing wrong with this.

But JavaScript gives us another way: 

const { name, age } = user;

This is called object destructuring.

Instead of accessing each property separately, we're telling JavaScript which properties we want to create variables from.

What is JavaScript matching when it sees this syntax?

For objects, destructuring works by matching property names. 

const user = {
  name: "Sai",
  age: 24
};

const { name, age } = user;

Conceptually: 

user
  ↓
name → "Sai"
age  → 24
  ↓
name variable
age variable

We can also give the variable a different name: 

const { name: userName } = user;

Here, name is the property we're looking for, while userName is the variable we create.

Arrays work slightly differently. 

const numbers = [10, 20, 30];

const [first, second, third] = numbers;

With arrays, destructuring is based on position. 

numbers

[10, 20, 30]
 ↓   ↓   ↓
first second third

So objects are matched by property name, while arrays are matched by position.

Spread Operator

Now consider an array: 

const numbers = [1, 2, 3];

Suppose we want to create another array containing those values. 

const newNumbers = [...numbers];

The three dots are the spread operator.

What does "spread" actually mean here?

The spread operator takes the elements of an iterable and expands them into the surrounding structure.

Conceptually: 

numbers
   ↓
[1, 2, 3]

...numbers
   ↓
1, 2, 3

So when we write: 

const newNumbers = [...numbers];

it is as if the values of numbers are being placed individually into the new array.

We can also add other values around them: 

const newNumbers = [0, ...numbers, 4];

The result is: 

[0, 1, 2, 3, 4]

Spread also works with objects. 

const user = {
  name: "Sai",
  age: 24
};

const updatedUser = {
  ...user,
  city: "Dallas"
};

The properties from user are spread into the new object. 

user
  ↓
name → "Sai"
age  → 24
  ↓
...user
  ↓
new object

One important detail is that if the same property appears again later, the later value wins. 

const updatedUser = {
  ...user,
  age: 25
};

The final value of age is therefore 25.

This becomes especially useful when creating a new object based on an existing one.

Rest Operator

Now we see the same three dots again: 

const [first, ...remaining] = numbers;

But this time, the three dots are not spreading values.

If spread expands values, what is happening here?

The rest operator collects the remaining values into a single variable. 

const numbers = [1, 2, 3, 4, 5];

const [first, ...remaining] = numbers;

Now: 

numbers

[1, 2, 3, 4, 5]
 ↓
first = 1

remaining
 ↓
[2, 3, 4, 5]

This gives us a useful mental model: 

Spread → expands

Rest → collects

The same ... syntax is being used for two different purposes depending on where it appears.

Rest is also useful in function parameters. 

function add(...numbers) {
  console.log(numbers);
}

add(10, 20, 30);

Inside the function, numbers becomes: 

[10, 20, 30]

Instead of defining a fixed number of parameters, the rest parameter collects the remaining arguments into an array.

Template Literals

Before template literals, combining text and variables often meant using string concatenation. 

const name = "Sai";

const message = "Hello " + name;

JavaScript provides another way to write this: 

const message = `Hello ${name}`;

This uses a template literal.

What makes `${...}` different from normal text?

Anything inside ${...} is evaluated as a JavaScript expression. 

const a = 10;
const b = 20;

const message = `The result is ${a + b}`;

The expression a + b is evaluated first, and its result becomes part of the string.

Template literals also make multiline strings easier to write because the line breaks can be included directly. 

const message = `
Hello
How are you?
Welcome!
`;

So the useful mental model here is simple: 

Template literal
      ↓
String + JavaScript expressions

Optional Chaining

Now let's look at a different problem.

Suppose we have: 

const user = {
  profile: {
    address: {
      city: "Dallas"
    }
  }
};

We can access the city with: 

user.profile.address.city

But what happens if profile doesn't exist? 

const user = {};

user.profile.address.city;

JavaScript tries to access address from undefined, which causes an error.

Can we ask JavaScript to continue only if the value exists?

This is where optional chaining comes in. 

user.profile?.address?.city

The ?. tells JavaScript to stop and return undefined if the value before it is null or undefined.

Instead of thinking of it as a shortcut, I find it easier to think of it as a safe way of continuing through a chain of properties. 

user
  ↓
profile exists?
  ↓
yes → address
  ↓
address exists?
  ↓
yes → city

Optional chaining can also be used when calling a function that may not exist. 

user.login?.();

If login exists and is callable, it can be called. Otherwise, JavaScript returns undefined instead of throwing because the property is missing.

Nullish Coalescing

Sometimes we don't just want to safely access a value. We also want a fallback when the value is missing.

For example: 

const username = null;

const name = username ?? "Guest";

The result is: 

"Guest"

The nullish coalescing operator, ??, uses the value on the right when the value on the left is null or undefined.

Why do we need `??` when JavaScript already has `||`?

The important difference is what each operator considers to be "missing."

The logical OR operator treats values such as 0, false, and an empty string as falsy. 

const count = 0;

const result = count || 10;

Here, result becomes 10.

But maybe 0 is a perfectly valid value.

With nullish coalescing: 

const count = 0;

const result = count ?? 10;

The result is: 

0

That's because ?? only falls back for null and undefined.

Optional Chaining + Nullish Coalescing

These two operators become especially useful when used together. 

const city =
  user?.profile?.address?.city ?? "Unknown";

We can read this almost like a sentence:

Try to get the city. If something along the way doesn't exist, or the final value is null or undefined, use "Unknown".

Optional chaining answers: 

Can I safely continue?

Nullish coalescing answers: 

If the value is missing, what should I use instead?

Putting the concepts together

These features can look like unrelated pieces of syntax when we first encounter them.

But they are all helping us work with data more clearly. 

const user = {
  name: "Sai",
  profile: {
    address: {
      city: "Dallas"
    }
  }
};

const { name } = user;

const updatedUser = {
  ...user,
  age: 24
};

const { profile, ...rest } = updatedUser;

const message = `Hello ${name}`;

const city =
  user.profile?.address?.city ?? "Unknown";

Each feature is solving a different problem. 

Destructuring
      ↓
Take values out by structure

Spread
      ↓
Expand values into a new structure

Rest
      ↓
Collect remaining values

Template literals
      ↓
Build strings using expressions

Optional chaining
      ↓
Safely access possibly missing values

Nullish coalescing
      ↓
Provide a fallback for null / undefined

The mental model 

JavaScript works with data
          ↓
We need to access values
          ↓
Destructuring helps us take values out
          ↓
Spread helps us expand values
          ↓
Rest helps us collect values
          ↓
Template literals help us build strings
          ↓
Optional chaining helps us safely access values
          ↓
Nullish coalescing gives us sensible fallbacks

What initially looks like a collection of small syntax features starts to make more sense when we look at the problems each one is trying to solve.

And this is where I think modern JavaScript becomes interesting.

The syntax is only the surface. Understanding what problem the language is solving underneath makes the syntax much easier to remember.
