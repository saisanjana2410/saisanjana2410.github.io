Passing State as Props — Who Actually Owns the State?

I understood that a parent could pass state to a child. What confused me was what happened next: does the child own that state, and how can the child change it?

The Confusion

Suppose a parent owns some state: 

function Parent() {
  const [count, setCount] = useState(0);

  return (
    <Child count={count} />
  );
}

The child receives count as a prop.

Parent │ │ count = 0 ↓ Child │ └── receives count

My first instinct was:

"If the child has the state now, doesn't the child own it?"

No.

Passing state as a prop does not transfer ownership of that state.

Who Owns the State?

The component that calls useState() owns that state. 

function Parent() {
  const [count, setCount] = useState(0);

  return (
    <Child count={count} />
  );
}

Here, Parent owns count. Child only receives its current value.

The child can read the prop: 

function Child({ count }) {
  return <p>Count: {count}</p>;
}

But it should not try to change it directly. 

count = count + 1; // ❌

So How Can the Child Change It?

This is where callbacks come in.

The parent can pass a function along with the state: 

function Parent() {
  const [count, setCount] = useState(0);

  function increment() {
    setCount(count + 1);
  }

  return (
    <Child
      count={count}
      onIncrement={increment}
    />
  );
}

The child receives the function: 

function Child({ count, onIncrement }) {
  return (
    <>
      <p>Count: {count}</p>

      <button onClick={onIncrement}>
        +1
      </button>
    </>
  );
}

The child isn't changing the parent's state directly. It is calling a function that the parent provided.

Child │ │ onIncrement() ↓ Parent's function │ │ setCount(...) ↓ Parent state changes

The Complete Cycle

Once the parent updates its state, the new value flows back down to the child.

Parent owns state ↓ passes state as props ↓ Child receives props ↓ User interacts with Child ↓ Child calls callback ↓ Parent updates state ↓ Parent re-renders ↓ new props ↓ Child receives the new value

So the child can trigger a state change, but it doesn't become the owner of that state.

What If Two Children Need the Same State?

Suppose two sibling components need to work with the same piece of data:

App / \ Input Display

Instead of keeping separate copies of the state, we move it to their common parent:

App name state / \ Input Display

This is called lifting state up.

The parent becomes the single source of truth and passes the value and necessary callbacks to its children.

Unidirectional Data Flow

This gives us one of the most important React mental models: data flows downward through props.

Parent owns the state │ props ↓ │ Child │ user interaction │ callback ↑ │ Parent │ state changes │ ↓ new props │ ↓ Child

People sometimes describe this as "child-to-parent communication," but the important detail is that the child isn't taking ownership of the parent's state.

The parent gives the child a function. The child calls it. The parent changes its own state, and the new value flows down again.

The Mental Model I Want to Remember

Props are values a component receives. State is data owned and managed by a component.

Passing state to a child does not transfer ownership.

If the child needs to cause a change, the parent can pass a callback. The child calls the callback, the parent updates its state, and the new state flows down as props.

Parent owns state → child receives props → child calls callback → parent updates state → new props flow down.

Once this clicked, props, state, callbacks, lifting state up, and one-way data flow stopped feeling like separate React rules. They became parts of the same model.
